# Как сравниваются два каталога во времени

FileSentinel отвечает на один вопрос: какие пути и байты изменились между двумя
снимками. Для каждого обычного файла сохраняются размер и SHA-256. Если заменить
`aaaa` на `bbbb`, размер останется прежним, а хеш изменится. Такой случай есть
в `test_same_size_content_changes_are_detected`.

`compare` сначала сравнивает множества путей. Новые попадают в added, исчезнувшие
в removed. У общих путей сравнивается запись с размером и хешем. Результат
сортируется, чтобы повторные запуски было удобно сопоставлять.

## Почему снимки лежат снаружи

Если сохранить JSON внутри сканируемого каталога, следующий обход включит сам
предыдущий снимок. CLI проверяет путь вывода и отклоняет такой запуск. Фильтры
тоже входят в формат: сравнивать снимки с разными исключениями запрещено.
Пошаговый пример есть в [example.md](example.md).

## Чтение и запись

`snapshot` обходит каталог без перехода по ссылкам. `digest_file` читает файл
потоком через открытый дескриптор. До, во время и после чтения сравниваются
идентичность файла, размер и время изменения. Ошибка чтения прерывает весь снимок.

На Windows lstat и fstat могут по-разному представлять ctime. Поэтому ctime
сравнивается между двумя вызовами одного интерфейса. Это отдельное решение
в коде, а не повод отключать проверку изменений файла.

`save_manifest` пишет временный файл рядом с назначением, сбрасывает буфер и
заменяет итоговый JSON через os.replace. Предыдущий снимок сохраняется до
успешной замены. В JSON записываются относительные пути с `/`, без имени
исходного диска и домашнего каталога.

Обход последовательный: для согласованного результата каталог должен быть
стабильным. Снимок хранит содержимое файлов, а права доступа и альтернативные
потоки Windows остаются вне формата. Исходный JSON нужно хранить отдельно от
изменяемых файлов, поскольку подписи у него нет.
